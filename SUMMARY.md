# Investigation Process Summary

- **Initial Execution & Environment Issues**: I first attempted to run the oracle using the system Python (3.14 / 3.9), but encountered silent exits and segmentation faults. I hypothesized the `oracle.py` module contained a marshaled `code` object compiled for a specific Python version. I verified this by installing different Python versions (`3.10`, `3.11`, `3.12`) via pyenv, eventually discovering that Python `3.12` executed the blob successfully.
- **Base Pricing Rule Discovery**: By isolating variables, I swept the `weight_kg` and `distance_km` parameters independently. I observed linear scaling, finding that distance linearly contributes $2.50 per km. By subtracting the distance component from the price, I was able to determine that weight contributes $40.00 per kg.
- **Rounding Hypotheses**: My initial hypothesis for weight was that it was charged purely linearly ($40/kg). However, testing fractional weights (e.g., 1.1kg) revealed a step-function behavior. I hypothesized a ceiling function was being used, and further testing confirmed `weight_kg` is rounded up to the nearest 0.5 kg (using `math.ceil(w * 2) / 2`).
- **Category Modifier Discovery**: By testing all categories against the established base formula, I discovered that "fragile" adds a $150 flat fee, and "electronics" adds a +30% modifier. I verified these modifiers are applied independently of distance and weight.
- **Non-Linear Discount Discovery**: During testing, I noticed that higher inputs (like `w=14, d=100`) unexpectedly broke the linear pricing curve, resulting in a lower price (e.g., $729 instead of $810). I formed the hypothesis that a volume discount was being applied. By probing exact thresholds (e.g., $800 vs $802.50 base prices), I confirmed a 10% discount applies strictly when the price > $800.
- **Coupon Code Analysis**: I hypothesized that coupons might have complex interactions with categories. However, testing the only valid coupon string ("WELCOME10") revealed it universally applies a flat $100 deduction to the final price, even allowing the total price to become negative.
- **The "Express" Parameter Red Herring**: I hypothesized that `express=True` would add a flat fee or percentage multiplier. After initial manual tests showed no effect, I ran large-scale brute force tests (thousands of random inputs) to find any edge cases where `express` changed the price. Finding none, I hypothesized that `express` was completely ignored.
